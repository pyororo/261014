# 법인카드 점검 도구 (오프라인 HTML)

Python과 Claude를 쓸 수 없는 내부망에서 쓰는 점검 도구입니다. **설치 없이 Chrome으로 여는 HTML 파일 1개**이며, 네트워크를 전혀 쓰지 않습니다.

- 반입할 파일: [`dist/법인카드점검_v2.4.html`](dist/법인카드점검_v2.4.html) (약 1MB). 이전 버전은 `dist/`에 그대로 둡니다.
- 점검 로직: CLAUDE.md 2장 (R01~R17, T-R1~T-R4, 위험점수·등급, 사전승인 문서번호 기재 건 저위험 조정)

## 보안 특성 (정보보호팀 검토용)

| 항목 | 내용 |
|---|---|
| 외부 통신 | 파일 머리의 Content-Security-Policy로 모든 네트워크 연결을 차단 (`default-src 'none'`, `connect-src 'none'`). 외부 스크립트·글꼴·이미지를 불러오지 않음 |
| 데이터 처리 | 불러온 엑셀은 브라우저 메모리에서만 처리. 서버로 전송하거나 디스크에 저장하지 않음 |
| 브라우저 저장 | 검토결과·의견만 Chrome의 localStorage에 임시 저장 (같은 PC·같은 브라우저에서만 보임) |
| 포함 라이브러리 | SheetJS Community Edition 0.18.5 (엑셀 읽기·쓰기, Apache-2.0, `src/vendor/`) |
| AI | 외부 AI를 호출하지 않음. 선별 사유·추가 확인사항·추가 점검항목 추천은 규칙과 집계로 생성 |
| 코드 | `src/` 아래 원본이 그대로 합쳐져 있어 HTML 파일 안에서 직접 읽어볼 수 있음 |

## 내부망 사용 방법

1. Chrome에서 HTML 파일을 엽니다 (더블클릭 또는 Chrome 창으로 끌어다 놓기).
2. **기준표 엑셀**을 준비합니다. 처음이면 **기준표 양식 내려받기**로 받은 `card-audit_reference-template.xlsx`에 실제 사내 기준을 입력합니다. 양식에 들어 있는 값은 교육용 가상값입니다. 기준표가 든 파일을 여러 개 불러오면 같은 시트는 덮어쓰지 않고 합칩니다(같은 사번·계정·업종코드 등은 나중 파일 값, 양식의 `(예시)` 행은 무시). 화면 위 줄에 시트별로 파일마다 몇 행을 읽었는지 표시됩니다.
   - `계정코드`: G/L 계정, G/L 계정명, 허용 가맹점업종(쉼표 구분), 건당 한도(원)
   - `업종코드`: 업종코드, 가맹점업종, 제한구분(금지/사전승인/주의/일반)
   - `공휴일`: 일자, 명칭 (주말은 자동 계산)
   - `점검기준`: 규칙ID, 점검항목, 위험가중치
   - `직원마스터`: 사번, 이름, 부서, 근무지 (R13 근무지 판단)
   - `휴가내역`: 사번, 이름, 휴가구분, 시작일, 종료일 (R17)
   - `추가조건`: 내부망에서 직접 추가하는 점검 조건 (아래 "추가조건 쓰는 법")
3. **엑셀 불러오기**로 기준표 엑셀과 SAP 추출 엑셀을 함께 고릅니다. 월별 파일은 나눠 불러와도 승인번호 기준으로 누적됩니다. SAP 파일의 시트 이름은 상관없고, 첫 행에 `승인번호`·`전표금액` 컬럼이 있으면 거래 시트로 인식합니다.
4. 점검 대상월을 고르고, 목록에서 건을 눌러 검토결과(적정/소명요청/부적정)와 의견을 입력합니다.
5. **결과 엑셀 저장**으로 `card-audit_result_YYYY-MM.xlsx`를 저장해 감사조서 증적으로 보관합니다. 맨 앞 `요약` 시트에 ① 검토결과별 건수·금액 ② 규칙별 ③ 부서별(지적 = 소명요청+부적정, 지적 많은 순) ④ 소명 처리 현황 표가 COUNTIFS·SUMIFS 수식으로 들어 있어, 엑셀에서 검토결과·소명결과를 고치면 바로 다시 계산됩니다(행 순서는 저장할 때 기준). 검토의견 뒤에 소명 관리 열(소명요청일·회신기한·회신일·소명결과·소명 요지·증빙번호)이 빈칸으로 들어 있어 엑셀에서 소명 관리대장으로 이어 쓸 수 있습니다(소명결과는 목록에서 선택). 이 파일을 다음에 SAP 엑셀과 함께 불러오면 검토결과·의견과 소명 열 내용이 복원됩니다.

6. **거래 조회** 탭에서 선별되지 않은 거래까지 조건(기간·검색어·계정·업종·부서·금액·선별 여부·휴일·취소 포함)으로 걸러 보고, **조회 결과 엑셀 저장**으로 원본 컬럼 그대로 저장할 수 있습니다.

## 점검 규칙 수정 (v1.9)

화면 오른쪽 아래 **✎ 점검 규칙 수정** 버튼(또는 점검 규칙표의 **규칙 수정**)으로 엽니다. 바꾼 값은 **적용**을 눌러야 반영되며, 적용하면 바로 다시 계산합니다.

- **단건·다건 규칙(R)**: 규칙마다 한 줄 설명, 사용 여부, 기준 숫자, 가중치. R01·R02·R03·R04·R06·R09·R13·R14·R16은 **세부 설정**에서 제외 업종, 대상 제한구분, 분할결제 묶는 범위(같은 날/N일 이내)·최소 건수, 상대방 표기 단어·'이 단어만 적으면 부실' 단어, 중복으로 볼 항목, 제목 단어↔업종 대응표, 원거리 제외 업종, 공용카드 판단 단어를 고칩니다. 판단 방식 자체를 바꾸려면 외부망에서 새 버전을 만듭니다.
- **추가조건(U)**: 화면에서 조건을 만들고 고치고 지웁니다(컬럼·비교·값, 같은 ID 안은 '그리고'). 기준표 추가조건 시트의 잘못된 행 안내와 전체 적중 건수도 여기서 봅니다.
- **기간 규칙(T)**: 사용 여부와 기준값.
- 고치는 동안 오른쪽에 대상월 선별 건수가 '현재 → 바꾼 뒤'로 나옵니다.
- 적용한 값은 이 PC 브라우저에 기억됩니다. **기준표 엑셀로 저장**하면 바뀐 가중치·추가조건과 `규칙설정` 시트가 들어간 기준표가 만들어지고, 이 파일을 불러오면 같은 설정으로 복원됩니다(다른 PC·다음 달용).
- **결과 엑셀 저장**에 `적용기준` 시트가 추가되어 그달 어떤 규칙·가중치·세부 설정으로 점검했는지(기본값과 다른 항목 포함) 함께 남습니다.
- 기본값(정답지로 검증한 설정)으로는 v1.8과 같은 결과가 나옵니다. 세부 설정을 바꾸면 검증 결과와 달라질 수 있으니 적용기준 시트를 증적과 함께 보관하세요.

## 추가조건 쓰는 법 (v1.1, 반입 없이 조건 추가)

기준표 엑셀의 `추가조건` 시트에 한 줄에 조건 하나씩 적고, 기준표를 다시 불러오면 바로 적용됩니다.

| 조건ID | 조건명 | 컬럼 | 비교 | 값 | 가중치 |
|---|---|---|---|---|---|
| U01 | 백화점 10만원 이상 | 가맹점업종 | 같음 | 백화점 | 2 |
| U01 | | 전표금액 | 이상 | 100000 | |
| U02 | 적요에 선결제 기재 | 전표 품목 텍스트 | 포함 | 선결제 | 3 |
| U03 | 금요일 저녁 접대비 | G/L 계정명 | 포함 | 접대비 | 1 |
| U03 | | 요일 | 같음 | 금 | |
| U03 | | 승인시 | 이상 | 18 | |

- **조건ID**: U01, U02…처럼 U로 시작합니다. 같은 조건ID의 행은 모두 만족해야 걸립니다(AND). 조건명과 가중치는 그 ID의 첫 행에 적습니다.
- **컬럼**: SAP 엑셀의 컬럼명을 그대로 쓰거나, 계산 컬럼(`요일`, `승인시`(0~23), `휴일`(Y/N), `승인월`(YYYY-MM), `공휴일명`, `시도`, `제한구분`)을 씁니다.
- **비교**: 같음, 다름, 포함, 미포함, 시작, 이상, 이하, 초과, 미만, 목록중하나(값을 쉼표로 여러 개), 비어있음, 비어있지않음
- 걸린 거래는 규칙 칩에 `U01`처럼 표시되고, 가중치가 위험점수에 더해져 등급에 반영됩니다. 선별 사유에는 "추가조건 '조건명' 해당"이 붙습니다.
- 잘못 적은 행(없는 컬럼, 쓸 수 없는 비교, 숫자가 아닌 금액 등)은 적용하지 않고 **점검 규칙 수정** 화면의 추가조건 탭에 몇 번째 행이 왜 틀렸는지 표시합니다. 같은 탭에서 조건별 적중 건수도 확인할 수 있습니다.
- 한 건씩 판단하는 조건만 가능합니다. "같은 날 3건 이상", "몇 개월 연속"처럼 여러 건을 묶어 보는 조건은 외부망에서 코드로 추가해야 합니다.

## 외부망에서 수정 → 재반입 절차

1. 내부망에서 문제를 **말로만** 정리해 옵니다. 실제 데이터·화면 캡처·결과 파일은 가져오지 않습니다.
2. 외부망에서 같은 상황을 가상데이터로 재현해 `src/`를 고칩니다.
3. 빌드: `./offline/build.sh 1.1` → `dist/법인카드점검_v1.1.html` 생성
4. 검증: `node offline/verify.js data/법인카드_가상데이터_202509-202608.xlsx` → 모든 항목이 **통과**여야 반입합니다 (v1.1부터 추가조건 판정 시험, v1.9부터 규칙 수정 설정 시험, v2.0부터 기준표 불러오는 순서 시험 포함 9개).
5. 아래 변경 이력에 바뀐 내용을 적고, HTML과 함께 반입 신청합니다.
6. 구글 드라이브 `법인카드점검PoC_교육준비/법인카드점검도구_HTML버전` 폴더([링크](https://drive.google.com/drive/folders/1F2TfKGW3dlr52vkDogSF25Mg0UXiXa-f))의 [버전 목록 문서](https://docs.google.com/document/d/1UwruKMYaYRt9-9KJ_-Ne-BoS6WqNZIvdl6jPRmaY5-M/edit)에 새 버전 행을 추가하고, 새 HTML을 같은 폴더에 올립니다. HTML은 약 1MB라 연결 도구로 올릴 수 없어 사용자가 직접 올립니다.
